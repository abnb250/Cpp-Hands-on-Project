# 任务7：手写 MyVector 模板——按编码顺序整理的需求

## 定位
- 难度：高到难。
- 目标：综合训练模板、动态数组、迭代器、完美转发、扩容安全。
- 原则：只实现 std::vector 的核心子集，重点在“模板 + 迭代器 + 扩容异常安全”。

## 第 1 步：定异常策略
- 优先使用标准库异常：std::out_of_range、std::length_error、std::bad_alloc。
- 下标访问越界抛 std::out_of_range。
- 容量请求超过 max_size 抛 std::length_error。
- 内存分配失败交给 new 抛 std::bad_alloc，不自己吞。
- 不要求派生自定义异常。

## 第 2 步：定成员变量
- 私有成员只保留必要的最少项：T* data_、std::size_t size_、std::size_t capacity_。
- 约定：size_ 是元素个数，capacity_ 是容量，data_ 管理原始内存。
- data_ 指向以 placement new 构造的元素，未使用区域是原始内存。
- 三者必须始终一致：data_ == nullptr 当且仅当 capacity_ == 0。

## 第 3 步：写构造函数
- 默认构造：空容器，data_ = nullptr，size_ = capacity_ = 0。
- 带容量构造：显式分配 capacity_ 个原始内存，size_ = 0。
- 带个数和初始值构造：分配并构造 n 个元素。
- []初始化列表构造：从 std::initializer_list<T> 构造。
- []区间构造：从一对迭代器 [first, last) 构造，支持任意可输入迭代器。
- []构造函数失败时已构造的元素必须正确析构，已分配的内存必须释放。

## 第 4 步：写析构函数
- 析构函数必须：
  - 对 [0, size_) 的每个元素调用 .~T()；
  - 用 operator delete 释放原始内存；
  - 标记 noexcept，不抛异常。
- 析构函数不能泄漏、不能重复析构、不能对未构造区域调用析构。

## 第 5 步：写迭代器
- 提供 T* / const T* 作为迭代器，或封装一个最小的随机访问迭代器类。
- 至少提供：begin()、end()、cbegin()、cend()，各有 const / 非 const 版本。
- 迭代器必须支持：*、++、--、==、!=、+、-、<、>，满足随机访问迭代器基本语义。
- 迭代器失效规则要明确：扩容后所有迭代器失效；insert/erase 后插入/删除点之后的迭代器失效。
- []用迭代器重写区间构造、insert、erase 的内部实现，保证“迭代器可用”不是摆设。

## 第 6 步：写元素访问
- operator[] 提供 const 和非 const 版本，返回 T& / const T&，按标准惯例不检查越界。
- at() 提供 const 和非 const 版本，越界抛 std::out_of_range。
- front()、back() 提供 const 和非 const 版本。
- data() 提供 const 和非 const 版本，返回原始缓冲区指针。
- 空容器调用 front()/back() 是未定义行为，不强制检查。

## 第 7 步：写容量接口
- size()、capacity()、empty()、max_size()，全部 noexcept。
- reserve(n)：只扩容不缩容；n <= capacity_ 时不做任何事；n > max_size() 抛 length_error。
- shrink_to_fit()：把 capacity_ 缩到 size_，可选实现。
- resize(n) / resize(n, value)：扩大时用 value（或 T()）填充新位置，缩小时析构多余元素。

## 第 8 步：写拷贝构造与拷贝赋值
- 拷贝构造：深拷贝，为新容器分配独立内存，逐个拷贝构造元素。
- 拷贝赋值：使用 Copy-and-Swap 惯用法。
- 自赋值安全。
- 拷贝过程中抛异常时，已构造的元素必须析构，已分配的内存必须释放，原对象（赋值场景）保持不变。

## 第 9 步：写移动构造与移动赋值
- 移动构造：标记 noexcept，接管 other 的 data_/size_/capacity_，把 other 置为空。
- 移动赋值：标记 noexcept，先释放自己的资源，再接管 other 的资源，把 other 置空。
- 自移动安全。
- 移动后 other 处于有效但未指定内容的状态，可安全析构、可重新赋值。

## 第 10 步：写 swap
- 成员 swap 或 friend swap，交换 data_/size_/capacity_。
- 标记 noexcept，只交换三个成员，不分配、不抛异常。
- 拷贝赋值、移动赋值、排序、扩容都依赖它。

## 第 11 步：写修改操作
- push_back(const T&) / push_back(T&&)：尾部追加，容量不足时扩容。
- pop_back()：析构最后一个元素，size_--；空容器调用是未定义行为。
- clear()：析构 [0, size_) 所有元素，size_ = 0，不释放 capacity_。
- insert(pos, value) / insert(pos, count, value) / insert(pos, first, last)：在指定位置插入，返回指向新元素的迭代器。
- erase(pos) / erase(first, last)：删除元素，返回删除后的下一个位置迭代器。
- 所有修改操作都要正确处理 size_、capacity_、元素析构和迭代器失效。

## 第 12 步：写完美转发
- emplace_back(Args&&... args)：用 std::forward<Args>(args)... 原地构造尾部元素，避免临时对象。
- emplace(pos, Args&&... args)：在指定位置原地构造元素。
- 参数必须用万能引用 Args&&...，转发时必须用 std::forward<Args>(args)...。
- emplace_back 必须支持 move-only 类型（如 std::unique_ptr<int>）。
- 提供 emplace_back 与 push_back 的对比测试，说明完美转发避免了几次拷贝/移动。

## 第 13 步：保证扩容安全（核心难点）
- 扩容流程必须是：
  1. 先分配新内存；
  2. 在新内存上构造/移动/拷贝元素；
  3. 全部成功后再析构旧元素、释放旧内存；
  4. 最后更新 data_/capacity_。
- 任何一步抛异常时：
  - 新内存上已构造的元素必须析构；
  - 新内存必须释放；
  - 旧 data_、旧 size_、旧 capacity_ 保持不变（强异常安全保证）。
- 优先使用 std::move_if_noexcept：
  - 如果 T 的移动构造是 noexcept，或 T 不可拷贝，用移动构造；
  - 否则用拷贝构造，保证扩容失败时旧元素仍可用。
- 可以用 std::unique_ptr<T[]> 或 RAII 包装临时持有新内存，避免手动释放遗漏。
