# 任务4：图书管理系统 OO 版——按编码顺序整理的需求

## 第 1 步：定异常策略
- 优先使用标准库异常：std::invalid_argument、std::out_of_range、std::runtime_error。
- 只有上层需要区分特定业务错误时，才派生自定义异常。
- 需要覆盖的错误：非法输入、重复 ID、资料不存在、已借出再借、未借出却归还、文件打开或读写失败。

## 第 2 步：写抽象基类 LibraryItem
- 定义抽象基类 LibraryItem。
- 基类必须提供虚析构函数。
- 基类提供虚函数接口：显示信息、借阅检查、类型标识。
- 每种资料包含：ID、标题、借阅状态。

## 第 3 步：写派生类 Book、Magazine
- 至少派生 Book、Magazine 两个具体类。
- 各自实现基类虚函数：显示信息、借阅检查、类型标识。
- 通过基类指针或引用多态展示资料信息。
- 不使用大量 if type == ... 判断类型。

## 第 4 步：定持久化接口 Storage
- 由高层定义 Storage 接口，声明 save / load 能力。
- 接口只依赖 LibraryItem 抽象，不依赖具体文件格式。
- 加载时要能根据类型标识恢复为对应的派生类型。
- 保存内容包含：资料类型、ID、标题、借阅状态。

## 第 5 步：写具体持久化 TextStorage
- TextStorage 实现 Storage 接口。
- 文件格式保持简单，例如文本行或简单分隔符。
- 程序启动时从文件加载数据。
- 程序退出或手动保存时写回文件。
- 文件打开或读写失败时抛出异常。

## 第 6 步：写管理类 Library
- 使用 STL 容器管理资料。
- 建议使用 std::unique_ptr 管理多态资料对象。
- 支持添加资料。
- 支持删除资料。
- 支持按 ID 查找资料。
- 支持列出全部资料。
- 支持借阅资料：已借出的不能再次借出。
- 支持归还资料：未借出的不能归还。
- 支持按标题排序。
- 统计资料总数、可借数量、已借出数量。
- Library 只依赖 Storage 抽象，不依赖 TextStorage 具体实现。

## 第 7 步：组装 main 与菜单
- main 中创建具体 TextStorage，并注入 Library。
- 提供简单命令行菜单，串起增删查、借还、排序统计、保存加载。
- main 是唯一同时认识 Storage 抽象和 TextStorage 实现的地方。

## 第 8 步：写测试
- 覆盖正常流程：添加、查找、借阅、归还、排序、统计、保存加载。
- 覆盖边界情况：空容器、重复 ID、不存在的 ID。
- 覆盖异常情况：已借出再借、未借出却归还、文件打开失败。
